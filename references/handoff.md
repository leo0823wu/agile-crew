# 工作階段之間的交接

專案紀錄是寫給「之後來查狀況的人」；交接單是寫給「馬上要接手的工作階段」。兩個都要有，用途不同。
壓縮對話（自動摘要）留下什麼沒辦法控制，只能當保險；交接以「寫好交接單＋開新的工作階段」為主。

什麼時候要交接照主檔〈一件事一個工作階段〉的三條判斷，這份只講怎麼交接。

## 1. 交接單：專案紀錄裡固定的一段

放在專案紀錄「目前狀況」的下面。**每次交接整段改寫，不往下加**；只有四項，每項寫不出來就寫「無」，不能留空：

```markdown
## 交接單

> YYYY-MM-DD HH:MM 寫。給下一個接手的工作階段；每次交接整段改寫，不累積。接手的人做完第一個動作後不用回頭改這段，下次交接再整段換掉。

- **下一步的第一個動作**：<寫到開哪個檔的哪一段、跑哪個指令；不是「繼續做 X」>
- **試過但沒用的方法**：<做法＋為什麼沒用；讓接手的人不用再試一次>
- **做到一半的狀態**：<改了還沒 commit／還沒推的檔；還在跑的背景工作與怎麼看結果；在等使用者回覆哪一題>
- **使用者這次講過的偏好**：<這次對話裡使用者講的、還沒寫進規則或紀錄別處的要求與決定>
```

寫的時候對照這幾點：

- 「第一個動作」要讓接手的人**不用問、不用找**就能開始：檔案寫完整路徑，指令寫整行。
- 「試過但沒用的方法」是專案紀錄最常缺的一項。這次猜錯的方向、跑過但沒結果的檢查都寫，附一句原因。
- 「做到一半的狀態」照實列：`git status` 看到的未 commit 檔、已 commit 沒推的分支、放在暫存區還沒搬走的檔（要留的先搬到專案資料夾再寫位置）。
- 「偏好」只放這次新講的。長期有效的同時寫進專案規則或本地規則，交接單這裡留一句指過去。
- 不寫密碼、金鑰、個資。
- 這件事已經全部做完、沒有要接下去的：整段改成一行「無（YYYY-MM-DD 已交付，沒有進行中的工作）」，免得下一個工作階段照舊的交接單做。

交接單之外，專案紀錄照常更新（「目前狀況」改寫成最新、「待辦」、「工作進度」加一列）。交接單不重抄這些。

## 2. 開新的工作階段：由 Claude 開，不靠使用者手動開

順序固定：**先寫完交接單，再開**。

1. 寫交接單、更新專案紀錄。
2. 看環境有沒有開新工作階段的工具（Claude 桌面 app 是 `mcp__ccd_session__start_session`；只列在延後載入的工具清單時先用 ToolSearch 載入）。
3. **有工具** → 直接把新的工作階段準備好：
   - `context` 用 `fresh`（不帶這個對話，才省得到）。
   - `prompt`（任務說明）**第一行固定寫** `交接單：<專案紀錄的完整路徑>`，接著把交接單四項原文貼上，最後一句寫「做完的樣子」。每週報表靠第一行認出這是接手的工作階段。
   - `background` 寫兩三句：這個專案是什麼、這件事的目標、不能碰的限制。不重講經過——經過在專案紀錄。
   - `initiation` 看是誰要開：使用者說「開新的」「另外開一個做」→ `user_asked`；使用者這句話講的是另一件事 → `offer`（只給標題，使用者選了「新的工作階段」再送說明）；是你自己判斷該交接（告一段落、對話太長的提醒）→ `own_initiative`（出現一張卡片，使用者按了才開始）。
   - 開完用一句話告訴使用者：新的工作階段叫什麼、接下來的事在那裡做。
4. **沒有工具**（終端機版、其他環境）→ 照舊提醒使用者開新的工作階段，並給一句可以直接貼過去的話：`交接單：<專案紀錄的完整路徑>，讀完照「下一步的第一個動作」接著做。`

還在等使用者回答的問題不會跟著過去：交接單「做到一半的狀態」要寫明在等哪一題，新的工作階段開工先看使用者回了沒。

## 3. 接手的工作階段怎麼開工

- 開工 hook（`session_brief.py`）對到專案時會把交接單帶進對話；沒帶到就自己讀專案紀錄的〈交接單〉。**先讀交接單，再讀「目前狀況」「待辦」**。
- 直接從「下一步的第一個動作」開始。交接單寫明已經做過的檢查、已經試過的方法，不重做。
- 交接單不夠用（要回頭問使用者之前做到哪、要重讀前一個工作階段讀過的一批檔才知道狀況）時，照做，但記下來缺的是哪一項——回顧時填進指標，並把缺的那一類補進上面第 1 節的寫法。

## 4. 量交接順不順

兩個指標：

| 指標 | 意思 | 怎麼量 |
|---|---|---|
| 接手問 | 接手後回頭問使用者「之前做到哪」「上次的結論是什麼」這類前一個工作階段已經知道的事，幾次 | 接手的工作階段在回顧的「指標摘要」寫 `接手問 N`（問法太多種，從紀錄檔用關鍵字找會漏，漏了反而看起來很順，所以由當事的工作階段照實填） |
| 接手重做 | 重做前一個工作階段已經做過的事（重讀同一批檔、重跑同一個掃描），幾件 | 回顧寫 `接手重做 N`；另外每週報表自動數「動手前讀的檔有幾個前一個工作階段也讀過、重跑幾個同樣的指令」 |

- 不是接手的工作階段不用寫這兩項。
- 每週報表（`scripts/token_weekly.py` 的〈交接〉一節，算法在 `scripts/handoff_metrics.py`）列出每個接手的工作階段：動手前使用者又講了幾次話、問了幾題、讀了幾個檔、其中幾個前一個工作階段也讀過、重跑幾個同樣的指令、開始改檔時對話多大。這些是客觀數字，**只當線索**：要改的檔本來就得讀一次，重複不等於浪費；數字偏高的那幾個再去看回顧寫的 `接手問`、`接手重做`。
- `scripts/team_metrics.py` 會把回顧裡的 `接手問`、`接手重做` 加總列出來。
