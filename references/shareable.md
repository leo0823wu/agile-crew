# 技能與本地分層：技能可以分享，本地持續精進

這個技能設計成**可以直接分享給別人**：技能資料夾裡只有通用的流程面、技術面內容，沒有任何個人或公司資料。
每個使用者自己的工作方式、公司慣例、專案細節，寫在**本地資料夾**，只留在自己的電腦。

兩層一起運作：
- **技能（通用層）**：越用越好的團隊流程與技術做法。任何人裝了都能用，也可以把通用的改進分享回來。
- **本地（個人層）**：這個人、這家公司、這些專案特有的規則與經驗。技能每次執行都會讀它，所以會越來越貼合這個使用者，但不會外流。

## 本地資料夾在哪（`<本地>`）

預設 `~/.claude/agile-crew-local/`；要放別處就設環境變數 `AGILE_CREW_LOCAL`。所有腳本與 hook 都用同一個規則找它。
本地資料夾**不在技能資料夾裡**，所以分享、推送技能時不會被帶出去。

| 檔案 | 內容 | 誰會讀 |
|---|---|---|
| `local-rules.md` | 這個使用者／公司的規則：紀錄放哪、專案總表在哪、部署慣例、檔案放置、回報格式偏好、要先讀的文件 | 每次開工（`SKILL.md` 第 0 步） |
| `lessons-local.md` | 只適用本地的踩坑，以及通用踩坑在本地的具體細節（同一個編號） | 開工時跟 `lessons-*.md` 一起看 |
| `retro-log.md` | 每次回顧的紀錄與〈趨勢〉 | 開工 hook 帶入 ⏳、回顧時加一列 |
| `skill-changelog.md` | 技能改版紀錄與成效（有效／沒效） | 開工 hook 帶入待驗證的、回顧第 0 步 |
| `private-terms.txt` | 不能出現在技能裡的字（公司名、專案名、人名、主機、內部用語） | `scripts/check_shareable.py` |
| `config.json` | 給 hook 用的本地路徑（`project_index` 專案總表、`work_root` 文件根目錄、`code_root` 程式碼根目錄），沒有就略過專案待辦與紀錄檢查；`record_gate` 段是收尾紀錄檢查的設定（觸發訊號、閒置切段時數、別名、忽略路徑、舊程式碼根目錄） | `hooks/session_brief.py`、`hooks/record_gate.py` |
| `record-gate.log` | 收尾紀錄檢查每擋一次記一行（時間、工作階段、哪份紀錄），之後算成效用 | `hooks/record_gate.py` 寫 |
| `lesson-ids.log`、`.lesson_id.lock` | 取號紀錄與鎖 | `scripts/lesson_id.py` |
| `scripts/` | 只適用某專案的腳本 | 需要時 |

**第一次用**：跑 `python -I ~/.claude/skills/agile-crew/scripts/init_local.py`，會建 `<本地>` 並把 `templates/` 的範本複製過去（已經有的不覆蓋）。
接著填 `local-rules.md`（你的慣例）與 `private-terms.txt`（不能外流的字）；`config.json` 有專案總表才填。
範本裡寫了**格式規定**（段落標題、每列以日期或編號開頭）：hook 與腳本靠這個格式解析，格式不對不會報錯、只是讀不到，所以不要改標題。
沒有本地資料夾也能用技能：開工提醒會提示建立，其他步驟照通用做法。

## 寫進哪一層：判斷規則

每次要寫東西（踩坑、回顧發現、規則、腳本）先問：**換一個人、換一家公司，這句話還有用、而且沒洩漏什麼嗎？**

| 寫進技能（通用） | 寫進本地 |
|---|---|
| 流程做法：先盤點、驗收才交付、回報格式、子代理分工 | 公司／個人的慣例：紀錄放哪個資料夾、用哪個專案總表、誰要被通知 |
| 技術做法：指令、參數、錯誤碼、工具的坑（PowerShell、Git Bash、Docker、PostgreSQL…） | 公司環境：主機名、IP、內部網址、帳號、跳板、部署路徑、port |
| 公開產品、框架、服務的名稱 | 公司內部系統名稱與內部用語、專案名、repo 名、人名 |
| 「（2026-10-29）又一次」這類日期與次數 | 「（某專案 2026-10-29）」裡的專案名、commit、測試類別、腳本路徑 |
| 使用者的原話（拿掉人名、專案名） | 使用者原話裡提到的人、專案 |

**一件事兩層都有用時拆開寫**：通用的做法寫進技能的那一列，具體位置與證據寫進本地（`lessons-local.md`〈本地細節〉用同一個 `L-` 編號）。
**整件事只適用本地**：寫進 `lessons-local.md`〈只適用本地的經驗〉，編號用 `lesson_id.py next --local` 取 `P-` 編號（跟技能的 `L-` 分開，技能更新新增編號時不會撞號）。
拿不準時：先寫本地，之後在定期技能優化時判斷能不能提煉成通用的。
**改寫時同一筆資料的每個欄位要一起抽象化**：例如主機換成代稱了，同一行的 port、帳號、路徑也要一起換（只換一個欄位最常漏）。
**技能檔裡不要寫 ⏳**：開工 hook 會把 ⏳ 當成待辦；作者自己的待辦寫進本地。

## 寫完技能一定要檢查

```
python -I ~/.claude/skills/agile-crew/scripts/check_shareable.py
```

- 掃 `<本地>/private-terms.txt` 的字＋通用樣式（email、私有 IP、使用者家目錄路徑），要 **0 行**。
- 碰到新的公司用語、專案名、人名、主機名，**先加進 `private-terms.txt`**（只列專有名詞會漏掉內部簡稱，要一起列）。
- 開工 hook 也會跑一次；有命中會出現在開工提醒裡。
- 分享前再用空的本地資料夾模擬新使用者：`AGILE_CREW_LOCAL=<空資料夾>` 跑一次 `hooks/session_brief.py`，看別人開工會看到什麼（不該看到你的待辦或歷史）。
- 改寫成通用版時**只刪私人資料，不准順手精簡**：改寫後「以後的做法」比原文短 5% 以上的列，要逐列確認少掉的只是私人資料。

## 分享技能

- 技能資料夾可以是 git repo；分享前跑 `check_shareable.py` 為 0。
- `.gitignore` 已排除 `_backup/`、`__pycache__/`。本地資料夾本來就不在技能裡。
- 別人拿到技能後：照上面「第一次用」建自己的本地資料夾；他的改進一樣分兩層，通用的可以回饋給技能。
