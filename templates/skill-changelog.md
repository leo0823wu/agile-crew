# 技能改版紀錄（每次改技能都記一列，之後驗證有沒有效）

回顧的目的是**讓團隊技能本身變好**，不是寫報告。所以每次回顧的主要產出是「技能改了什麼」，而且每個改動都要能在之後驗證：
**改了 → 下次碰到同類工作時看問題有沒有再發生 → 有效就留、沒效就換做法或撤掉**。

## 什麼算「改技能」

技能的 `SKILL.md` 流程、`agent-briefs.md` 子代理範本、`edge-case-checklist.md` 盤點清單、`lessons-*.md` 升級成機制、`hooks/`、`scripts/`，
以及本地的 `local-rules.md`、專案 `CLAUDE.md`／記憶裡的規則。只在 lessons 加一列文字**不算**（那是記錄，不是改技能）。

## 怎麼寫

- 回顧（技能 `references/retro.md` 第 3 步）每改一處，在下表最上面加一列，「成效」先寫 `⏳ 待驗證`。
- **預期效果要寫成看得到的訊號**：哪個 L-xxx 不再 +1、哪類 QA 退回不再出現、哪個等待變短。寫不出訊號的改動，先想清楚再改。
- 回顧第 0 步：這次工作碰到某列要解決的問題 → 填成效：
  - `✅ 有效（日期：問題沒再發生／被擋下）`
  - `❌ 沒效（日期：還是發生）` → 同一次回顧就要換做法（升一級：文字 → 範本／清單 → 腳本／測試 → hook），新做法另加一列，並在這列寫「→ 改用 <新列日期> 那列」
  - 兩次以上 ✅ 就把成效改成 `✅ 已證實`，之後不用再追
- 改了一陣子都沒碰到相關工作的，維持 ⏳，不要硬填。
- 撤掉某個改動（造成誤擋、拖慢、沒人用）也要記一列，寫原因。

**格式（腳本靠它解析，不要改）**：段落標題 `## 改版紀錄`；每列以 `| YYYY-MM-DD |` 開頭；第 5 欄「成效」以 ✅／❌／⏳ 開頭。
